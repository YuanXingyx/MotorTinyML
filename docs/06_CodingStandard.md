# 编码规范

## 适用范围

本规范适用于 MotorTinyML 项目的固件、Python 工具、测试及相关配置文件。具体语言规范可在技术负责人确认技术栈后补充。

## 通用原则

1. 代码应清晰、可读、可测试。
2. 保持模块职责单一，避免将全部功能放入单个文件。
3. 使用一致且具有含义的命名。
4. 避免重复代码和无说明的常量。
5. 公共接口应提供必要文档。
6. 错误必须得到明确处理，不得静默忽略。
7. 不提交密钥、口令或本地环境配置。
8. 不擅自引入依赖或改变架构。

## 文件与模块

- 按功能组织文件，不创建含义不清的目录。
- 文件名和模块名应准确表达职责。
- 生成文件与手写代码应明确区分。
- 大型数据、模型及构建产物不得直接提交，除非技术负责人批准。

## 注释与文档

- 注释用于解释原因、约束和非显而易见的行为。
- 避免重复描述代码本身。
- 修改公共接口时同步更新 API 文档。
- 修改行为或配置时同步更新 README 和相关设计文档。

## 测试要求

- 每个功能变更必须包含适当的测试或验证记录。
- 修复缺陷时应补充能够复现问题的测试。
- 提交前执行适用的自动化测试和静态检查。
- 无法自动测试的内容必须记录手动验证步骤和结果。

## 待补充规范

以下内容由技术负责人确定后补充：

- C/C++ 语言版本和具体规则
- Python 版本、格式化和静态检查工具
- 固件模块边界
- 测试框架
- CI 检查项
