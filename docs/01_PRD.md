## 1. 产品愿景

MotorTinyML 面向资源受限的嵌入式平台，建立电机状态数据采集、数据集处理、AI 模型训练和设备端 TinyML 推理的完整工程链路。

## 2. 项目目标

1. 完成已批准 STM32F103 平台的基础 Bring-up。
2. 开发并验证已批准的传感器驱动。
3. 建立可复现、可追溯的数据采集流程。
4. 建立数据集处理、质量检查和版本管理流程。
5. 训练并验证满足批准指标的电机状态模型。
6. 将已验证系统迁移至 STM32F407 平台。
7. 在目标平台完成 TinyML 推理部署和验证。
8. 完成系统集成、测试和项目发布。

## 3. 目标用户

目标用户及使用场景待 Tech Lead 确认。候选用户包括嵌入式系统开发人员、电机状态监测研究人员和 TinyML 学习验证人员。

## 4. 产品范围

### 范围内

- STM32F103 Bring-up
- 传感器驱动开发
- 电机状态数据采集
- 数据集处理
- AI 模型训练和验证
- STM32F407 平台迁移
- TinyML 设备端部署
- 系统集成、测试和发布

### 范围外

除非 Tech Lead 另行批准，以下内容不在当前范围内：

- 云端平台
- 移动应用
- Web 管理系统
- 商业量产硬件
- 未批准的传感器、协议、模型或部署平台

## 7. 硬件需求

以下项目待 Tech Lead 确认：

- STM32F103 和 STM32F407 的具体型号及开发板
- 电机与电机驱动器
- 传感器类型、型号和接口
- 调试器、电源、连接器及数据接口

## 8. 软件需求

以下项目待 Tech Lead 确认：

- STM32CubeIDE 与 Arm GNU Toolchain 版本
- Python 版本和依赖管理方式
- AI 训练框架和 TinyML 推理运行时
- 模型转换、量化、测试、格式化和静态检查工具

## 9. 验收标准

- 所有已批准的功能需求均已实现。
- 所有已批准的非功能指标均已达到。
- 固件、数据集、训练和部署流程可复现。
- STM32F407 设备端推理通过验收。
- 自动化测试与硬件测试通过。
- 文档、测试报告和部署说明完整。
- 已知限制得到明确记录。
- 满足 [完成定义](08_DefinitionOfDone.md)。

## 10. 依赖与风险

- 依赖 Tech Lead 的架构、硬件和工具链决策。
- 数据质量可能影响模型效果。
- STM32 资源限制可能影响模型部署。
- 工具链版本不一致可能导致构建不可复现。
- 项目周期较短，必须严格控制范围。
